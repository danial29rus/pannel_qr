# Проверка панели и интеграции Витрины — 25 ноября 2026

Изменения выполнены в локальной копии. На действующий сервер изменения не отправлялись; его база, DNS и webhook не менялись. Развёртывание нового сервера ещё не выполнено.

## Исправления

- Недельный лимит маршрута определял день недели после перевода московской полуночи в UTC. Граница могла сдвигаться на сутки. Теперь недели строго Пн–Вс по Москве.
- Финансовые дневные/недельные/месячные лимиты приведены к тому же московскому календарю.
- Отчёты и журнал используют исключающую верхнюю границу даты; наивные даты и обратные диапазоны отклоняются. Для отчёта установлен предел 366 дней.
- Добавлены текущая, прошлая и произвольная неделя, календарный месяц и сегодняшний день. График строится по реальным успешным платежам и заполняет пустые дни нулями.
- Защищены от устаревших ответов поиск платежей/пользователей, загрузка истории, лимиты проекта и отчёты. Добавлен таймаут запросов и читаемые ошибки валидации.
- Поиск находит локальный ID, ID провайдера, merchant ID и номер заказа. `%` и `_` обрабатываются как обычные символы поиска.
- Удалены вымышленный график, неработающее уведомление и глобальный MutationObserver, меняющий ограничения полей. При переключении проекта поля интеграции очищают секреты и загружают настройки выбранного проекта.
- На мобильных экранах меню больше не скрывается: нижняя навигация, меню остальных разделов, карточки платежей/маршрутов/пользователей, адаптивные формы и безопасная область iPhone.
- Добавлены `/ready`, журналирование ошибок сверки, приватные атомарные дампы, исключение env/секретов из Docker-контекста, lock-зависимости и `npm ci`. Vite обновлён до исправленной версии; npm audit не обнаружил уязвимостей на момент проверки.
- Установщик использует заданные домены и порты, поддерживает один домен для UI/API, не перезаписывает существующие Nginx-host и повторно читает новые секреты перед Compose. Резервная база изолируется именем проекта, worker включается отдельно.
- Добавлен универсальный JSON API provider: настраиваемые create/status paths, JSON request template, response paths, status mapping, Bearer/header auth и опциональная HMAC-подпись. Preset заполняет API-контракт Витрины.
- Vitrina preset вызывает hosted checkout MulenPay `/sbp`, читает `data.qrpayload` и отдаёт партнёру только прямой `https://qr.nspk.ru/` URL. Если NSPK URL не получен после retries, локальная транзакция сохраняется как failed, provider attempts/event сохраняются, маршрут получает cooldown, а партнёру отправляется failure callback; hosted URL не уходит как QR.
- Добавлен partner endpoint с двумя секретами: Auth token и HMAC Secret key. Принимает UUID/сумму, выбирает email из пула, создаёт платёж через выбранный provider route, возвращает direct NSPK link и статус; incoming create/status запросы подписаны и ограничены 5-минутным timestamp window.
- Email reservation сохраняется до сетевого вызова. Повтор после timeout не выбирает новый email, а Витрина получает тот же UUID для идемпотентного создания. Новый UUID может выбрать тот же email, эксклюзивная блокировка email между разными незавершёнными заказами не реализована.
- Callback нового API подписывается `X-Panel-Timestamp`/`X-Panel-Signature`; polling доступен по отдельному status URL. Reconciliation queue выбирает terminal транзакции `external-api:*`, чтобы отправить callback после смены статуса.
- 422 validation responses и backend warnings показывают field/type/message, но не echo исходных значений, email или secrets.
- Добавлен `scripts/test_partner_payment.py`: скрыто запрашивает два partner keys, отправляет подписанный create, показывает payment/QR URLs, открывает checkout по флагу `--open` и опрашивает статус. Платёж через production provider является реальным.
- Добавлен `scripts/diagnose_vitrina_payment.py`: по существующему UUID проверяет Vitrina status и MulenPay `/sbp`, не создавая новый платёж; секреты скрыто запрашиваются и не печатаются.
- Повтор внутреннего создания с тем же Idempotency-Key и другой суммой/валютой/пользователем/направлением возвращает 409.

## Выполненные проверки

- **97 backend-тестов прошли, 3 opt-in PostgreSQL-теста пропущены** в основном прогоне. Отдельно на временной PostgreSQL 16 применены все миграции до `0011_external_payment_request`; все три opt-in tests прошли.
- Unit/API тесты покрывают HMAC, create/status, email reservation, повтор UUID, прямой NSPK extraction через MulenPay `/sbp`, отказ при отсутствии NSPK URL, статусы и валидацию JSON adapter. HTTP провайдеров подменяется.
- **4 теста JS** проверяют московский понедельник при воскресенье UTC, воскресенье, переход года и високосный месяц.
- Production-сборка React и production Compose configuration завершились успешно.
- Vitrina API token и panel partner keys не добавлялись в репозиторий. Реальные платежи не создавались.
- Chrome: реальный оборот на тестовых данных, переключение недель, журнал, суммовой фильтр, сброс и история платежа. Ошибок выполнения JS не обнаружено.
- Chrome с эмуляцией **320, 360, 390, 430 и 844 px** в предыдущей проверке: нижняя навигация, переход в журнал, меню «Ещё», горизонтального переполнения не было. Новый JSON API/partner-key блок прошёл production build; отдельный ручной браузерный проход по новой форме ещё не выполнялся.

## Что ещё требуется на сервере

Нужны SSH-доступ к VPS, DNS/TLS `panel.vitrina-studio.ru`, новый Vitrina Bearer token для provider connection и отдельная пара Auth token/Secret key для партнёра. Реальные платежи не создавались; первый тестовый платёж и статус нужно проверить после настройки сервера и подключения действующих API credentials.

Автоматическое переключение между серверами, репликация базы, нагрузочный тест и проверка на физических iPhone/Android не выполнялись. `/api/v1/transactions/qr` остаётся legacy endpoint для direct NSPK URL; для Vitrina hosted checkout используется новый signed external payments API. Партнёру нельзя выдавать provider/admin tokens.
